# Технический радар для «Будущее 2.0»

Кольца (rings):
- **Adopt** – используем как базовый выбор.
- **Trial** – пробуем на пилотах/отдельных доменах.
- **Assess** – изучаем, делаем PoC.
- **Hold** – не используем в новых инициативах, планируем вывод.

Квадранты:
- **Platforms** – платформы и инфраструктура.
- **Tools** – инструменты и продукты.
- **Techniques** – подходы и методологии.
- **Languages & Frameworks** – стек разработки.

## Platforms

| Технология / платформа | Статус (ring) | Роль в архитектуре | Поддерживаемые бизнес‑сценарии |
|------------------------|---------------|--------------------|---------------------------------|
| Data Lakehouse (объектное хранилище + табличный формат Iceberg/Delta/Hudi + SQL‑движок) | **Adopt** | Целевая аналитическая платформа и витрины данных вместо монолитного DWH | Быстрая подготовка отчётности; кросс‑доменная аналитика (медицина + финтех + партнёры); подготовка датасетов для ИИ; масштабирование под сотни ТБ и новые бизнесы |
| Облачная платформа (Yandex Cloud / VK Cloud / др.) | **Adopt** | IaaS/PaaS для Lakehouse, интеграционного слоя, AI‑сервисов и BI | Масштабирование отчётности и вычислений; повышение отказоустойчивости; быстрый запуск новых окружений под домены и новые направления |
| Domain‑oriented environments (отдельные окружения: Medical, Fintech, AI, Corporate, Partners) | **Trial** | Логическое и физическое разделение инфраструктуры по доменам | Независимое развитие клиник, финтех‑ и ИИ‑направлений; уменьшение кросс‑влияния релизов; подготовка к Data Mesh‑подходу |
| Legacy DWH на SQL Server 2008 | **Hold** | Историческое хранилище и источник данных меддомена | Временное обеспечение текущих отчётов клиник; плавная миграция в Lakehouse; отсутствие новой логики внутри DWH |
| ESB на Apache Camel (старая шина) | **Hold** | Легаси‑интеграции между системами | Поддержка существующих связей на период миграции; постепенный перевод критичных потоков в новый integration layer |

## Techniques

| Подход / методология | Статус (ring) | Роль в архитектуре | Поддерживаемые бизнес‑сценарии |
|----------------------|---------------|--------------------|---------------------------------|
| Domain‑Driven Design (DDD) для данных и систем | **Adopt** | Выделение доменов (Medical, Fintech, AI, Corporate, Partners) и их границ ответственности | Независимое развитие доменов; снижение связности; ясная ответственность за данные (Data as a Product) |
| Data Lakehouse архитектура | **Adopt** | Объединение гибкости Data Lake и управляемости DWH | Ускоренная аналитика; единая витрина для BI и ИИ; отсутствие дублирования между разными хранилищами |
| Data Mesh (как целевой организационный подход) | **Assess / Trial** | Децентрализованное владение данными на уровне доменов + общие платформенные сервисы и стандарты | Масштабируемая интеграция новых бизнес‑направлений (фарма, электроника); снижение нагрузки на центральную команду DWH; ускорение вывода продуктов в доменах |
| Data Governance (политики, роли, процессы управления данными) | **Adopt** | Управление качеством данных, доступом, SLA, каталогизацией | Соответствие медицинским и финансовым регуляторам; доверие к отчётности; удобная работа доменных команд с данными |
| Event‑driven интеграции (CDC, событийные потоки) | **Trial** | Событийная интеграция доменов вместо чисто пакетных интеграций через ESB | Поддержка near real‑time сценариев (онлайн‑скидки, онлайн‑скоринг, оповещения); снижение задержек и нагрузки на DWH |
| Infrastructure as Code (Terraform/Ansible) | **Adopt** | Описание инфраструктуры данных и интеграций кодом | Быстрое и воспроизводимое развёртывание окружений под домены; масштабирование в облаке; снижение операционных рисков |

## Как использовать этот радар

- **Краткосрочно (горизонт ~1 год):**
    - Фокус на переводе аналитики в **Lakehouse (Adopt)**.
    - Ввод в строй **Integration Layer, Orchestrator, Self‑Service BI, Data Catalog (Adopt/Trial)**.
    - Закрепление **DDD, Data Governance, IaC** как базовых практик.

- **Среднесрочно (2–3 года):**
    - Эволюция в сторону **Data Mesh (Assess → Trial → Adopt)**.
    - Постепенный вывод технологий из **Hold** (SQL Server 2008 DWH, PowerBuilder, старый ESB) по мере появления замен в доменах и платформе данных.
